# 5. Wasm 코드 생성

> 공통 규칙은 [../README.md](../README.md)를 본다.

- 상태: 초안
- 이전 단계: 의미 분석
- 다음 단계: 브라우저 실행

## 1. 하는 일

브라우저에서 실행할 Wasm 모듈을 생성한다.

### 처리 방식

- 수식은 Wasm 산술 명령으로, `\foreach`는 Wasm 제어 흐름으로 변환한다. Canvas 호스트의 그리기 함수를 가져오고 `draw()`를 내보낸다.
- 모듈 생성에 실패하면 이를 보고한다.

## 2. 입력

- 출처: 의미 분석
- 형식: 검증된 AST와 코드 생성에 필요한 심볼 정보.

아래 JSON은 데이터 구조를 보여 주는 예시다. 토큰과 트리는 일부만 표시했으며 필드명은 초안이다.

```json
{
  "ast": {
    "kind": "Draw",
    "points": [
      {
        "x": 0,
        "y": 0
      },
      {
        "x": 1,
        "y": 0
      }
    ],
    "line": 1,
    "column": 1
  },
  "symbols": []
}
```

## 3. 출력

- 형식: 컴파일러 패키지에서는 `.wasm` 바이트를, JSON 응답에서는 base64로 인코딩한 모듈을 반환한다.
- 화면에 보여주는 방식: 모듈의 텍스트 표현(형식 미정).

### 출력 키

컴파일러는 바이트를 생성한다. JSON 출력에서는 해당 바이트를 `wasmBase64` 필드에 담는다.

| 키 | 타입 | 내용 |
|---|---|---|
| `wasmBase64` | 문자열 | 완전한 `.wasm` 모듈을 base64로 인코딩한 문자열. 브라우저에서 바이트로 디코딩한 뒤 모듈의 `draw()`를 호출한다. |

#### API 응답 키

공통 README의 응답 형식 초안은 `output`과 `errors`를 사용한다. JSON 예시는 `output`에 담기는 값만 보여 준다.

| 키 | 타입 | 내용 |
|---|---|---|
| `output` | 단계 출력 또는 `null` | 아래 예시에 해당하는 단계 데이터. 에러 복구 결과도 담을 수 있다. 반환할 결과가 없으면 `null`이다. |
| `errors` | 진단 객체 배열 | 이 단계에서 발생한 진단 목록. 진단이 없으면 빈 배열이다. |
| `errors[].kind` | 문자열 | 진단 종류. |
| `errors[].message` | 문자열 | 사용자에게 표시할 진단 메시지. |
| `errors[].line`, `errors[].column` | 정수 또는 `null` | 1부터 세는 소스 줄과 열. 소스 위치가 없는 진단에서는 둘 다 `null`이다. |

아래 예시 모듈은 빈 `draw()`를 내보낸다.

```json
{
  "wasmBase64": "AGFzbQEAAAABBAFgAAADAgEABwgBBGRyYXcAAAoEAQIACw=="
}
```

## 4. 에러

| 종류 | 조건 | 메시지 예시 | 위치 정보 |
|---|---|---|---|
| 내부 코드 생성 | 앞 단계에서 허용한 AST 노드, 연산자 또는 함수의 Wasm 변환 규칙이 없음. | `no Wasm translation for AST node` | 확인할 수 있으면 해당 AST 노드. |
| 내부 코드 생성 | 분석을 통과한 노드 참조나 루프 변수에 필요한 바인딩 또는 로컬 슬롯이 없음. | `missing binding for loop variable 'i'` | 확인할 수 있으면 해당 참조. |
| 내부 코드 생성 | 생성한 임포트 또는 `draw` 익스포트가 합의한 Canvas 계약과 맞지 않음. | `invalid signature for Canvas import 'moveTo'` | 원인을 찾을 수 있으면 해당 AST 노드. |
| 내부 코드 생성 | 섹션을 인코딩할 수 없는 경우 등 모듈 인코더가 바이너리 생성에 실패함. | `failed to encode Wasm section` | 원인을 추적할 수 있으면 해당 AST 노드. |
| 내부 코드 생성 | 백엔드에서 생성한 바이트를 검증하는 경우 모듈이 검증을 통과하지 못함. | `generated Wasm module failed validation` | 원인을 추적할 수 있으면 해당 AST 노드. |

의미 분석을 통과한 뒤에도 발생할 수 있는 에러다. 앞 단계에서 발생한 컴파일 에러는 해당 단계의 진단으로 유지한다.

- 에러가 났을 때의 복구 방식: 앞 단계에 컴파일 에러가 있으면 코드 생성을 건너뛴다. 사용할 수 있는 모듈을 만들 수 없는 에러가 발생하면 생성을 중단한다.
- 에러가 있을 때의 출력 형태: 코드 생성에 실패하면 Wasm 바이트 없이 출력값 null과 진단을 반환한다.

## 5. API

- 엔드포인트: `POST /api/codegen` (제안)
- 요청 본문: 입력 절의 데이터를 받는다. JSON 필드명은 미정이다.
- 응답 본문: 출력과 진단 목록을 반환한다. 공통 README의 `output`과 `errors`는 응답의 초안이다.

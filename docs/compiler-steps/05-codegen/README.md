# 5. Wasm code generation

> For common rules see [../README.md](../README.md).

- Status: Draft
- Previous step: Semantic analysis
- Next step: Browser execution

## 1. What it does

Generate the Wasm module that the browser executes.

### How it works

- Emit Wasm arithmetic instructions for expressions and Wasm control flow for `\foreach`. Import drawing operations from the Canvas host and export `draw()`.
- Report a failure to generate the module.

## 2. Input

- Source: Semantic analysis
- Format: A validated AST and the symbol information needed to generate code.

The JSON below illustrates the data shape. Token lists and trees may be excerpts, and field names are provisional.

```json
{
  "ast": {
    "kind": "Draw",
    "points": [
      {
        "x": 0,
        "y": 0
      },
      {
        "x": 1,
        "y": 0
      }
    ],
    "line": 1,
    "column": 1
  },
  "symbols": []
}
```

## 3. Output

- Format: A `.wasm` module as bytes in the compiler package and base64 in the JSON response.
- How it is shown on screen: Text representation of the module (format undecided).

### Output keys

The compiler produces bytes. `wasmBase64` is the field used to carry those bytes in the JSON output.

| Key | Type | Contents |
|---|---|---|
| `wasmBase64` | string | Base64 encoding of the complete `.wasm` module. The browser decodes this string to bytes and invokes the module’s `draw()` export. |

#### API response keys

The common README proposes `output` and `errors` as the response fields. The JSON example shows only the value inside `output`.

| Key | Type | Contents |
|---|---|---|
| `output` | stage output or `null` | Stage data with the shape shown in the example. It can contain a recovered result. Use `null` when the stage has no result to return. |
| `errors` | array of diagnostic objects | Diagnostics produced by this stage. An empty array means the stage produced none. |
| `errors[].kind` | string | Diagnostic category. |
| `errors[].message` | string | Diagnostic message shown to the user. |
| `errors[].line`, `errors[].column` | integers or `null` | 1-based source line and column. Both are `null` when the diagnostic has no source location. |

The example module exports an empty `draw()` function.

```json
{
  "wasmBase64": "AGFzbQEAAAABBAFgAAADAgEABwgBBGRyYXcAAAoEAQIACw=="
}
```

## 4. Errors

| Kind | Condition | Example message | Position info |
|---|---|---|---|
| Internal code generation | An AST node, operator, or function accepted upstream has no Wasm translation. | `no Wasm translation for AST node` | The relevant AST node, if available. |
| Internal code generation | A supposedly resolved node reference or loop variable lacks a binding or local slot. | `missing binding for loop variable 'i'` | The reference, if available. |
| Internal code generation | The emitted imports or `draw` export do not match the agreed Canvas contract. | `invalid signature for Canvas import 'moveTo'` | The triggering AST node when known. |
| Internal code generation | The module encoder fails to produce the binary, for example because it cannot encode a section. | `failed to encode Wasm section` | The relevant AST node when traceable. |
| Internal code generation | The emitted module fails validation, if the backend validates generated bytes. | `generated Wasm module failed validation` | The related AST node when traceable. |

These failures can occur after successful semantic analysis. Compiler errors from earlier stages remain attached to those stages.

- Recovery on error: Skip code generation after any earlier compiler error. Stop emitting the module when a code generation failure makes it unusable.
- Output shape when there are errors: For a code generation failure, return a null output and diagnostics without Wasm bytes.

## 5. API

- Endpoint: `POST /api/codegen` (proposed)
- Request body: Takes the data described in the Input section. JSON field names remain open.
- Response body: Returns the stage output and diagnostics. The common README describes `output` and `errors` as the draft response shape.

# 3. AST 변환

> 공통 규칙은 [../README.md](../README.md)를 본다.

- 상태: 초안
- 이전 단계: 파서
- 다음 단계: 의미 분석

## 1. 하는 일

파스 트리를 의미 분석에서 사용할 AST로 바꾼다.

### 처리 방식

- 문법 규칙을 `Node`, `Draw`, `Foreach`, 좌표, 수식의 AST 노드로 변환한다. 구두점과 중간 문법 노드를 제거하면서 수식의 묶임과 소스 위치를 보존한다.
- 파서가 건너뛴 문장은 파서의 진단을 사용한다.

## 2. 입력

- 출처: 파서
- 형식: 파서가 만든 전체 또는 부분 파스 트리.

아래 JSON은 데이터 구조를 보여 주는 예시다. 토큰과 트리는 일부만 표시했으며 필드명은 초안이다.

```json
{
  "rule": "draw",
  "children": [
    {
      "kind": "DRAW",
      "lexeme": "\\draw",
      "line": 1,
      "column": 1
    }
  ],
  "line": 1,
  "column": 1
}
```

## 3. 출력

- 형식: 명령과 수식 노드 및 소스 위치를 담은 AST.
- 화면에 보여주는 방식: 파스 트리 다음에 표시하는 AST.

### 출력 키

단계 출력은 `body`에 문장 목록을 담는 `Program` 노드다. 예시는 `Draw` 노드 하나를 발췌한 것이다. AST 노드에는 공통으로 `kind`, `line`, `column`을 둔다. 좌표 객체는 `x`, `y`를 사용하고, 나머지 키는 `kind`에 따라 달라진다.

| 키 | 타입 | 내용 |
|---|---|---|
| `kind` | 문자열 | `Program`, `Draw`, `Node`, `Foreach` 등 노드 종류. |
| `line` | 정수 | AST 노드가 시작하는 소스 줄 번호. 1부터 센다. |
| `column` | 정수 | AST 노드가 시작하는 소스 열 번호. 1부터 센다. |
| `body` | 문장 노드 배열 | `Program`과 `Foreach`에 속한 문장을 소스 순서대로 담는다. |
| `points` | 좌표 또는 노드 참조의 배열 | `Draw`의 경로를 이루는 점을 순서대로 담는다. |
| `name` | 문자열 | `Node` 선언, `NodeRef` 또는 `Variable` 식의 이름. |
| `position` | 좌표 객체 | `Node`를 선언한 위치. |
| `x`, `y` | 숫자 또는 수식 객체 | 좌표의 가로·세로 성분을 각각 담는다. |
| `variable` | 문자열 | `Foreach`가 선언하는 루프 변수 이름. |
| `start`, `end` | 숫자 또는 수식 객체 | `Foreach` 범위의 처음 값과 마지막 값을 각각 담는다. |
| `operator` | 문자열 | `Unary` 또는 `Binary` 식의 산술 연산자. |
| `operand` | 숫자 또는 수식 객체 | `Unary` 식의 피연산자. |
| `left`, `right` | 숫자 또는 수식 객체 | `Binary` 식의 왼쪽·오른쪽 피연산자를 각각 담는다. |
| `function` | 문자열 | `Call` 식의 함수 이름. 예를 들어 `sin`, `cos`, `sqrt`가 있다. |
| `argument` | 숫자 또는 수식 객체 | `Call` 식에 전달한 인자. |

#### API 응답 키

공통 README의 응답 형식 초안은 `output`과 `errors`를 사용한다. JSON 예시는 `output`에 담기는 값만 보여 준다.

| 키 | 타입 | 내용 |
|---|---|---|
| `output` | 단계 출력 또는 `null` | 아래 예시에 해당하는 단계 데이터. 에러 복구 결과도 담을 수 있다. 반환할 결과가 없으면 `null`이다. |
| `errors` | 진단 객체 배열 | 이 단계에서 발생한 진단 목록. 진단이 없으면 빈 배열이다. |
| `errors[].kind` | 문자열 | 진단 종류. |
| `errors[].message` | 문자열 | 사용자에게 표시할 진단 메시지. |
| `errors[].line`, `errors[].column` | 정수 또는 `null` | 1부터 세는 소스 줄과 열. 소스 위치가 없는 진단에서는 둘 다 `null`이다. |

```json
{
  "kind": "Draw",
  "points": [
    {
      "x": 0,
      "y": 0
    },
    {
      "x": 1,
      "y": 0
    }
  ],
  "line": 1,
  "column": 1
}
```

## 4. 에러

| 종류 | 조건 | 메시지 예시 | 위치 정보 |
|---|---|---|---|
| 앞 단계 구문 | 파서가 복구 중 문장 하나를 건너뜀. | `expected ';'` | 파서가 기록한 소스 위치. |
| 내부 AST 변환 | 파스 트리에 AST 변환 규칙이 없는 문법 규칙이 들어 있음. | `no AST mapping for parse rule` | 확인할 수 있으면 해당 규칙의 시작. |
| 내부 AST 변환 | 정상으로 처리된 파스 트리 노드에 필수 자식이 빠져 있거나 자식의 종류가 예상과 다름. | `malformed draw parse-tree node` | 확인할 수 있으면 해당 규칙의 시작. |
| 내부 AST 변환 | 렉싱과 파싱을 통과한 토큰 값을 예상된 AST 표현으로 바꿀 수 없음. | `cannot convert numeric token to AST value` | 확인할 수 있으면 해당 토큰. |

구문 항목은 파서가 이미 보고한 진단이다. 내부 변환 에러는 파스 트리의 계약 또는 컴파일러 구현에 문제가 있음을 뜻한다.

- 에러가 났을 때의 복구 방식: 파서가 복구한 문장을 변환한다. 변환 에러가 하위 트리 하나에 국한되면 해당 부분을 건너뛰고 독립된 문장을 계속 변환한다.
- 에러가 있을 때의 출력 형태: 복구할 수 있으면 부분 AST와 새로 발생한 변환 진단을 반환한다. 사용할 수 있는 AST가 없으면 출력은 null이다. 앞 단계의 파서 진단은 한 번만 표시한다.

## 5. API

- 엔드포인트: `POST /api/ast` (제안)
- 요청 본문: 입력 절의 데이터를 받는다. JSON 필드명은 미정이다.
- 응답 본문: 출력과 진단 목록을 반환한다. 공통 README의 `output`과 `errors`는 응답의 초안이다.

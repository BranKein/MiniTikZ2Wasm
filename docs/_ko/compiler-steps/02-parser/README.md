# 2. 파서

> 공통 규칙은 [../README.md](../README.md)를 본다.

- 상태: 초안
- 이전 단계: 렉서
- 다음 단계: AST 변환

## 1. 하는 일

토큰 스트림이 CFG의 어떤 규칙에 대응하는지 보여 주는 파스 트리를 만든다.

### 처리 방식

- 토큰 스트림에 CFG를 적용한다. 소스가 문법에 어떻게 대응하는지 화면에서 볼 수 있도록 파스 트리에 문법 규칙 노드와 구두점을 남긴다.
- 예상 밖의 토큰과 너무 일찍 끝난 입력을 보고한다.

## 2. 입력

- 출처: 렉서
- 형식: 렉서가 만든 토큰 목록과 각 토큰의 소스 위치.

아래 JSON은 데이터 구조를 보여 주는 예시다. 토큰과 트리는 일부만 표시했으며 필드명은 초안이다.

```json
[
  {
    "kind": "DRAW",
    "lexeme": "\\draw",
    "line": 1,
    "column": 1
  }
]
```

## 3. 출력

- 형식: 문법 규칙 노드, 말단 토큰, 소스 위치를 포함하는 파스 트리.
- 화면에 보여주는 방식: 파스 트리.

### 출력 키

단계 출력은 파스 트리의 루트다. 예시는 트리에서 규칙 노드 하나를 발췌한 것이다.

| 키 | 타입 | 내용 |
|---|---|---|
| `rule` | 문자열 | 이 노드가 나타내는 CFG 규칙 이름. 예를 들어 `draw`가 있다. |
| `children` | 규칙 노드 또는 토큰 객체의 배열 | 소스 순서대로 나열한 자식 노드. 하위 문법 규칙은 같은 구조를 재귀적으로 사용하고, 말단은 [렉서 토큰 필드](../01-lexer/README.md#3-출력)를 사용한다. |
| `line` | 정수 | 규칙이 시작하는 소스 줄 번호. 1부터 센다. |
| `column` | 정수 | 규칙이 시작하는 소스 열 번호. 1부터 센다. |

#### API 응답 키

공통 README의 응답 형식 초안은 `output`과 `errors`를 사용한다. JSON 예시는 `output`에 담기는 값만 보여 준다.

| 키 | 타입 | 내용 |
|---|---|---|
| `output` | 단계 출력 또는 `null` | 아래 예시에 해당하는 단계 데이터. 에러 복구 결과도 담을 수 있다. 반환할 결과가 없으면 `null`이다. |
| `errors` | 진단 객체 배열 | 이 단계에서 발생한 진단 목록. 진단이 없으면 빈 배열이다. |
| `errors[].kind` | 문자열 | 진단 종류. |
| `errors[].message` | 문자열 | 사용자에게 표시할 진단 메시지. |
| `errors[].line`, `errors[].column` | 정수 또는 `null` | 1부터 세는 소스 줄과 열. 소스 위치가 없는 진단에서는 둘 다 `null`이다. |

```json
{
  "rule": "draw",
  "children": [
    {
      "kind": "DRAW",
      "lexeme": "\\draw",
      "line": 1,
      "column": 1
    }
  ],
  "line": 1,
  "column": 1
}
```

## 4. 에러

| 종류 | 조건 | 메시지 예시 | 위치 정보 |
|---|---|---|---|
| 구문 | 문장이 시작할 자리에 알 수 없는 명령이나 허용되지 않는 토큰이 있음. | `expected a MiniTikZ statement` | 예상 밖의 토큰. |
| 구문 | 문장 끝에 세미콜론이 없음. | `expected ';' after draw statement` | 다음 토큰 또는 입력 끝. |
| 구문 | 여는 괄호·중괄호가 없거나 닫는 기호가 없거나 짝의 순서가 잘못됨. | `expected '}' to close foreach body` | 예상 밖의 토큰 또는 입력 끝. |
| 구문 | 좌표 성분이나 구분 쉼표가 빠졌거나 좌표 성분이 너무 많음. | `expected ',' between coordinate components` | 처음 마주친 예상 밖의 토큰 또는 입력 끝. |
| 구문 | 그리기 경로에 `--` 구분자 또는 그 뒤의 점이 없음. | `expected a path point after '--'` | 다음 토큰 또는 입력 끝. |
| 구문 | 노드 선언에 이름, `at`, 위치 중 하나가 빠져 있음. | `expected 'at' after node name` | 다음 토큰 또는 입력 끝. |
| 구문 | 반복문 헤더에 변수, `in`, 범위 구분 기호, 범위 끝점 중 하나가 빠져 있음. | `expected a range endpoint after '...'` | 다음 토큰 또는 입력 끝. |
| 구문 | 반복문 헤더 뒤에 본문을 여는 중괄호가 없음. | `expected '{' to start foreach body` | 다음 토큰 또는 입력 끝. |
| 구문 | 산술 연산자의 피연산자가 없거나 인접한 피연산자 사이에 연산자가 없음. | `expected an expression after '+'` | 다음 토큰 또는 입력 끝. |
| 구문 | 함수 호출의 구두점 위치가 잘못됐거나 문법에서 요구하는 인자가 빠져 있음. | `expected a function argument` | 예상 밖의 토큰 또는 입력 끝. |
| 구문 | 문법에서 그림 환경을 요구하는 경우 환경의 시작·끝이 빠졌거나 서로 맞지 않거나 환경 뒤에 토큰이 남음. | `expected end of tikzpicture` | 예상 밖의 토큰 또는 입력 끝. |

최종 CFG에 따라 허용되는 구문과 오류 복구를 재개할 토큰이 결정된다.

- 에러가 났을 때의 복구 방식: 가능하면 문장이나 블록의 경계에서 파싱을 다시 시작한다. 닫는 기호를 찾을 때 중첩 깊이를 고려하고 입력 끝에서는 멈춘다.
- 에러가 있을 때의 출력 형태: 정상 문장이 담긴 부분 파스 트리와 구문 진단을 반환한다.

## 5. API

- 엔드포인트: `POST /api/parse` (제안)
- 요청 본문: 입력 절의 데이터를 받는다. JSON 필드명은 미정이다.
- 응답 본문: 출력과 진단 목록을 반환한다. 공통 README의 `output`과 `errors`는 응답의 초안이다.
